Yes — and there are real official terms for both things you're describing. Let me name them, then diagram it.
The terminology you're looking for
What you described
Official term
"pregnants, children, etc… important priority people"
Vulnerable Sectors (or priority/vulnerable groups) — standard DRRM/DSWD language
The per-evac-center breakdown of those counts
Evacuation Center Vulnerability Profile (or Needs Assessment)
"every brgy has needs"
Request for Assistance (RFA) — the actual term used in LGU/NDRRMC paperwork
"who donated what to where"
Assistance Ledger / Resource Mobilization Tracker — NDRRMC SitReps call this "Assistance Extended"
Nice bonus: your DAFAC form already uses these codes — remember Code: A - Older Person, B - Lactating Mother, C - PWD. So you're not inventing categories; you're reusing DSWD's own vulnerable-sector codes. That's a strong defense point.
The analogy that makes it click
It's a gift registry (like a wedding/baby registry) for disaster relief.
The evacuation center posts what it needs ("we have 12 pregnant women → we need maternity kits")
Donors (PCF/PHO) see the list and claim items ("MDRRMO will send 20 maternity kits")
The registry shows what's already fulfilled vs. still needed, so nobody sends 500 sacks of rice to one barangay while another gets zero
That last part is the real problem it solves: uncoordinated duplicate donations. Same theme as your whole capstone — structure prevents waste and blind spots.

Key design insight: the barangay shouldn't hand-type these counts. They're already inside DSWD's DAFAC records (ages, sex, health condition, Code A/B/C). Let the system aggregate them automatically — that way the vulnerable-sector profile is derived evidence, not another number someone guessed.
